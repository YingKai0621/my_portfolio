# Technical architecture

Proposed stack: Next.js App Router, React 19-compatible version, TypeScript strict, Tailwind CSS v4, Motion (`motion/react`), shadcn/ui, Aceternity and Magic UI registries, next-intl, npm, Git, optional Vercel deployment. Playwright is reserved for P11, not installed or configured in P0–P10. Verify installed Node version and current framework requirements before initializing. Choose mutually compatible stable versions, lock dependencies, report exact versions; do not blindly upgrade existing projects.

```text
src/
  app/[locale]/
    layout.tsx
    page.tsx
    projects/[slug]/page.tsx
    research/page.tsx       # optional if dedicated route approved
  components/
    ui/                    # inspected registry components
    sections/
    navigation/
    motion/
    custom/
  content/                 # typed facts, project slugs, stats, links
  i18n/                    # locale config, request, navigation
  lib/
messages/en.json
messages/vi.json
public/images/{profile,projects,achievements,placeholders}/
public/cv/                 # sanitized PDF only when approved
tests/e2e/                # create/configure in P11 only
docs/
```

Use actual supported next-intl routing setup for chosen Next.js version (middleware/proxy naming may vary). Locales en and vi, English default proposed. Prefer locale prefixes `/en`, `/vi` for deterministic sharing/SEO; root redirects to chosen locale or English using supported routing. Maintain translated metadata, canonical and alternates/hreflang; shared stable project slugs. Set HTML lang accurately; use Intl for numbers/dates. Avoid hydration mismatch from browser-only effects. Validate translated long strings and Vietnamese accents.

Keep facts and metrics typed and independent of presentation; translations keyed by stable IDs. Components receive data/locale rather than import duplicate CV text. Use server-rendered content and narrowly scoped client components. Dynamic import heavy effects where beneficial, static placeholder with fixed dimensions. No global client-only wrapper just for animation. Use local mock assets or SVG shapes, not random remote photos. Use Next image optimization when appropriate; no unlicensed fonts or images.

P2 V3 Hero follows this boundary: the server-rendered `Hero` supplies localized text and verified external links; `.poster-portrait-layer` remains empty until an owner-approved transparent asset exists; `PosterReveal` is the small client island for the replayable entrance and animates `.poster-portrait-asset` only if one is present; `HeroCubes` retains the official Isometric registry component in a lazy-mounted environment layer. Floating Dock, Encrypted Text and Layout Text Flip stay available in source but are not rendered in this Hero.

P5 follows the same server/client boundary: `EngineeringResearch` renders the heading and concise research copy on the server; `CapabilityExplorer` owns only explicit cloud-emphasis selection and the visible open technology groups, while `CapabilityIconCloud` owns the pausable/drag-capable canvas loop. `src/content/expertise.ts` stores stable group keys and verified technology-mark associations; descriptions and controls live in `messages/en.json` and `messages/vi.json`. The cloud is never the sole source of technical information: every technology name is rendered in ordinary HTML, including research tools, and the still cloud remains visible under reduced motion.

P6 keeps the same boundary: `Journey` server-renders localized education, competition-rank and research story content. `src/content/journey.ts` contains only stable, replaceable photo paths; translated copy stays in `messages/en.json` and `messages/vi.json`. `JourneyZipper` is the only client island; GSAP 3.15.1 and its included ScrollTrigger synchronize the original SVG slider, shrinking zipper lips, detached teeth, flap separation and arrival departure on one pinned, scrubbed timeline. It is created only for desktop with no reduced-motion preference and reverted on route/media changes. Mobile and reduced-motion users receive an unpinned static photo threshold; the complete story remains in normal DOM flow regardless of animation or JavaScript. Licensed stock photo slots are explicitly disclosed, not claimed as personal evidence, and are to be replaced with authentic owner assets when provided.

P7 **PROJECT GLACIER** supersedes FORM IN MOTION. `ProjectGlacier` server-renders EN/VI chapter copy; `GlacierExperience` is the client island and lazy-imports the Three scene near the viewport. `src/lib/glacier/manifest.ts` contains the provisional asset URL, semantic clips and asset-specific node names; `character.ts` owns Meshopt decoding, normalization, rig/clip mapping and material-slot classification. `animation-adapter.ts` samples clip time deterministically from normalized scroll progress; `shot-plan.ts` defines four camera compositions; `scroll-director.ts` owns one reversible, pinned GSAP timeline; `lighting.ts` owns lights and the environment map; `quality-policy.ts` caps DPR; `scene.ts` owns one renderer, RAF scheduling, visibility and disposal; `material-controller.ts` contains original glacial color, holographic band and ordered-dither shader branches. No character-specific node names are used in camera or scroll code. The browser-loadable asset is ignored by Git and is for local development only pending permission confirmation; see `docs/P7_ASSET_PROVENANCE.md`. Reduced motion is unpinned and static, and WebGL failure yields readable HTML chapter titles. No extra dependency or P8 scene was introduced.

H2.1 temporarily unmounts `ProjectGlacier` from the homepage; its modules remain for later choreography, so no second character canvas is active. `GlacialHero` server-renders the owner's name, specialization and real destinations; `GlacialHeroStage` dynamically imports one Three scene after hydration only in development. The scene reuses the P7 character loader/manifest and DPR policy, but keeps its own replaceable opening camera, material grade and light rig. The first paint is a stable HTML/CSS editorial composition, whether WebGL or the provisional GLB is unavailable. Idle/activation motion ends after 4.5 seconds, pointer response is on demand, and rendering stops offscreen, in hidden tabs and under reduced motion. The previous P2 `Hero`, official cubes and poster reveal remain in source as a reversible fallback. Production builds do not request the provisional GLB until rights are confirmed.

H2.2/H2.3 mounts `GlacialCinematic` in place of the H2.1-only `GlacialHero`; both that component and the P2 poster remain development fallbacks. `GlacialCinematic` server-renders the owner's identity and localized chapter text. `GlacialCinematicStage` alone owns the bounded desktop GSAP ScrollTrigger pin and authoritative 0–1 progress coordinate; it updates DOM chapter layers and forwards the same value to a single lazy-loaded `cinematic-scene.ts` canvas. H2.4 extends that pin to ~6.2 viewport-heights for meaningful clip/camera motion, not an empty spacer. `cinematic-shot-plan.ts`, `cinematic-animation.ts`, `cinematic-materials.ts` and `cinematic-environment.ts` independently own camera, skeletal sampling, per-slot PBR/shader changes and the disposable procedural landing architecture. The environment follows the animated hips only during Digital World; it is not a second render loop. On mobile chapter text flows naturally; reduced motion and production use static HTML/CSS and the regular About. The reusable `character.ts` adapter, `hero-lighting.ts`, H2.1-only `hero-materials.ts` and DPR policy remain separate replacement boundaries. The GLB is requested **only in local development**. `About` remains an independent semantic server component with its approved introduction, identity cards and achievement pillars; H2.4 removes the duplicated About heading and personality copy from the cinematic stage, which instead uses a short localized handoff. `#about` and `#work` remain direct normal-flow anchors. No second character renderer or global smooth-scroll controller is mounted.

H2.5 retains those boundaries but re-directs the desktop stage to four typography beats over 9 viewport-heights. The independent shot, clip, material and environment samplers use overlapping absolute-progress ranges, while non-overlapping masked title windows prevent double exposure. The separate Human Side panel is removed; a short Bone reveal releases directly into the existing normal-flow About. Mobile remains unpinned and reduced motion remains static. See `docs/H2_5_STORYBOARD.md` for the reference comparison, timing map and unresolved provisional-asset risks.

H2.6 supersedes that final handoff. `GlacialCinematic` now server-renders the approved P3 introduction, personal note, three Explorer/Engineer/Builder traits and Experience & Achievements pillars inside the one cinematic opening; `page.tsx` no longer mounts the old standalone `About`. Desktop pins the single stage for 14 viewport-heights and maps absolute progress to DOM, camera, four existing skeletal clips, original material shader, new `cinematic-backdrop.ts` spectral field, `cinematic-type.ts` depth-occluded outline typography, fixed architectural environment, root leap/landing and deterministic impact response. `#about` resolves to the in-stage introduction coordinate; `#work` bypasses the stage. Mobile is unpinned and condensed; reduced-motion/production render readable static personal content without loading the provisional GLB. There is still one renderer, no second scroll controller and no public GLB authorization. See `docs/H2_6_CINEMATIC_STORYBOARD.md` for the authored progress map and limitations.

Scripts for P0–P10: `dev`, `build`, `lint`, `typecheck` (names may adapt to verified scaffold). Run typecheck and lint at each phase completion; run build when necessary. Verify locales, dock, reduced motion, project routes, and mobile overflow manually where practical, recording viewport and observed results. In P11, install/configure Playwright and browsers, add `test:e2e`, and run automated checks; store any screenshots as review artifacts, not public assets. Before P11, report automated E2E as DEFERRED, not FAILED. No production deploy, external analytics, secrets or public CV until owner approval.

H2.7 retains the unified H2.6 DOM but centralizes travel, typography windows, contact and review positions in `cinematic-timing.ts`: 28 viewport-heights, direct scrub, no second clock. `cinematic-aura.ts` owns three depth-tested ribbons and `cinematic-afterimages.ts` owns two independent skeletons/mixers sharing immutable geometry. Pose sampling, right-hand additive grip, camera, energy, world and impact remain deterministic. Mobile/low-core tiers omit ghosts; reduced motion stays static. Remove permanent chapter `will-change` promotion to avoid text-paint failure on direct anchors. WebGL failure reverts the pin to the existing static layout. The development-only inspector is opt-in via `?cinematicDebug=1` and seeks the real trigger, not a second progress state. See `H2_7_CHOREOGRAPHY_REVIEW.md` for observations, timing and unresolved rig/visual limits.

H2.8A/B corrects a hidden Three.js mixer binding-cache interaction: `cinematic-animation.ts` restores its last animation-only quaternion for every controlled joint before the mixer sample, captures the new base, then applies bounded head/neck/spine/finger offsets. It also samples a deterministic root yaw; afterimage rigs follow the same orientation. `cinematic-shot-plan.ts` adds explicit rear holds and target-relative orbital camera interpolation, avoiding a chord through the model. The 28-viewport ScrollTrigger remains the only progress coordinate; duplicate callback values are skipped before scene/DOM updates. Development-only `cinematicNeutral`/`cinematicSource` query modes isolate the rig without altering production. See `H2_8_ANIMATION_REVIEW.md` for reference and pose evidence.

H2.9.1 supersedes **only** H2.8's artificial rear-view choreography: the root yaw and its supporting additive torso offsets are removed, including the delayed afterimage orientation. `cinematic-shot-plan.ts` keeps ordinary smooth shots and held intervals, but marks a direct camera cut at progress `.44` from an elevated full-body composition to a left-weighted helmet/shoulder close-up. At the boundary, position, target and FOV switch together; the character, clip, materials, backdrop and aura continue sampling the same absolute scroll progress. The close-up holds until `.56` before the existing later camera movement. On narrow screens, a cut-synchronous horizontal camera pan keeps the helmet within the viewport and eases out during the later move. The H2.8 quaternion-restoration fix and 28-viewport desktop scroll span remain intact. See `H2_9_1_HARD_CUT_REVIEW.md` for frame evidence and limits.
